# 主游戏剧情优化

## Problem

目前多个角色重复相同的抽象劝告，感情推进缺少具体事件。32 层默认已营救米歇尔、50 层默认走完 35 层，与可选择的探索顺序冲突。部分剑盾台词未本地化，35 层记事本把显露暗墙误写为全部打开。

## Goals

- 保留 31 个主线场景编号，润色对白、行为及伏笔回收。
- 爱音的口语与嘴硬、素世的克制和迟疑、米歇尔不经意的关心有区别；感情由两人具体相处推进。
- 32 层按米歇尔被抓／已救／尚未经历分别说话，50 层兼容捷径和正常路线。
- 使用现有不同表情素材；爱音说话时右侧保持当前对话对象，不固定跳成素世。

## Non-Goals

不改怪物数值、地图、机关、奖励、战斗先攻、存档格式；不生成新 CG；不增加好感度或分支结局。

## Design Principles

信息提示必须可执行；不让角色预知尚未经历的事件；CG 仍全窗显示；揭面只发生在 50 层；已有一次性标记不改名、不清空。

## Acceptance Scenarios

```gherkin
Feature: 剧情与实际探索顺序一致
  Scenario: 营救前后抵达32层
    Given 玩家尚未救出米歇尔或已经救出她
    When 播放骑士队长对白
    Then 分别提示二层牢笼或承认营救
    And 不声称尚未完成的营救已经完成
  Scenario: 捷径抵达50层
    Given 玩家没有完成35层约定
    When 播放终幕
    Then 不虚构35层的约定或二层初见
    And 素世亲自解释头套与舞台幻象
  Scenario: 对话形象保持一致
    Given 米歇尔或其他 NPC 正与爱音交谈
    When 爱音发言或切到旁白
    Then 对方立绘不被默认素世替换
  Scenario: 兼容既有游戏
    Given 存档已经记录已看场景
    When 继续游戏
    Then 原有一次性标记仍有效
    And 地图奖励和机关规则不改变
```

## Design

`StoryScript.h` 维护对白和表情；只读进度上下文来自既有场景标记。`MainWindow` 接入上下文及对应立绘，保留触发点与存档接口。`StoryPresentation.h` 的轻量立绘状态记录左右角色。正文每页保持短段落，早期不告白，结尾回应开场排练约定。

## Implementation Phases

1. 补回归断言并确认旧文失败。
2. 改写现有场景、补进度分支、表情和对话对象衔接。
3. 更新关键提示及剧情文档，检查一次，测试并构建原路径。

## Testing Strategy

测试场景非空、关键任务提示、各进度组合、无提前揭面、立绘资源引用以及对话对象持续性。运行剧情、机制、战斗反馈测试，不写入真实玩家存档。

## File Inventory / Out of Scope

涉及 `UI/StoryScript.h`、`UI/StoryPresentation.h`、`UI/MainWindow.cpp`、`UI/BossBattlePresentation.h`、剧情测试及文档。既有 CG 与其他小游戏素材不变；不提交或推送当前未完成的其他工作。
